# Security Policy

## Reporting a vulnerability

Please do not publish details of an undisclosed security vulnerability in a public issue.

Report security problems privately to the project maintainers through the security contact configured for the repository. Include:

- A description of the vulnerability.
- Affected version or commit.
- Steps to reproduce.
- Expected and observed behavior.
- Any relevant logs, traces or proof of concept that can be shared safely.

Avoid including credentials, private keys, personal information or production data in reports.

## Scope

Security reports involving the database engine, HTTP API, authentication and authorization, TLS, drivers, persistence, cluster communication and deployment configuration are welcome.

## Disclosure

The maintainers will evaluate reports, work on a fix and coordinate disclosure when appropriate. Public disclosure should happen after a fix or mitigation is available whenever practical.

## Dependencies

CaimanDB uses third-party open-source dependencies. Dependency vulnerabilities should be reported when they create a concrete security impact for CaimanDB.
